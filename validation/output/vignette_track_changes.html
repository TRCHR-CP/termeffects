# ggeffectsAdjusted predictions

After fitting a model, it is useful to generate model-based estimates (expected values, or adjusted predictions) of the response variable for different cobinations of predictor values. Such estimates can be used to make inferences about relationships between variables--adjusted precitions tell you: what is the expected outcome for certain values or levels of my predictors? For complex models, visualizations of marginal means and adjusted predictions are often far easier to understand and intuititively demonstrate associations of predictors and outcomes.

## Methods

`ggeffectstermeffects` computes marginal mean and adjusted predictions at representative values: the meanpredictors of interest vary over a grid, and all other predictors are held at representativetheir valuesmedian (numeric) or most common value (categorical), or averagedat acrossvalues predictorschosen fromwith statistical models`at`. The result is returned as a data frame with consistent structure, with a view towards ggplot plotting.

We call predictors of interest (ie. the non-marginalized terms) focal terms.



# From p-ggeffects to termeffects

The`termeffects` began as `p-ggeffects`, package is ana 'generalization' of the `ggeffects` package with a focus on non-linear interactions, and non-trivial marginalizations. 
Particularly, the deviations from `ggeffects` are focused on the introduction of `parameterized_model` objects, regular grid generation for the purpose of 2d-heatmap 
plotting, and simultaneous inference. `termeffects` keeps these features but no longer depends on `ggeffects`: it computes the predictions and their joint uncertainty itself.


## Parameterized models
A `parameterized_model` is a data structure consisting of a tuple of a fitted regression model, a map into the variable space of the model--particularly,
it is viewed as a continuous parameterization of the continuous predictor variables of the models. Moreover, the `parameterized_model` structure tracks
various auxiliary data.

We view parameterized models as a 'generalization' of generalized linear models. Consider the example $y \sim f_\beta(x) + \varepsilon$, where $f_\beta$
is the function $x \mapsto \beta^T x$. Call the domain of interest of $f_\beta$, $\Omega'$. For a mapping $\phi: \Omega \to \Omega'$, by composition, we
obtain a 'model' $y \sim f_\beta \circ \phi (z) + \varepsilon$. This is the classical example of a generalized additive model--the 'pullback' of the model 
$f_\beta$ by the basis functions $\phi$. Notice however, that a data set $(Y, X)$ in $\Omega'$ does not in general induce an estimate of $\beta$ (viewed 
as the coefficients of $f\circ \phi$). Indeed, the points of $X$ may not lie in $\phi(\Omega)$, and even if so, there may not be a unique preimage. 

In this light, rather than as a regression model, we view parameterized models instead as generalizations of marginalization by taking $x_i = c$. Indeed, taking
$f_\beta: \mathbb R^n \to \mathbb R$ as above, the describe marginalization is equivalent to the parameterization $\phi: \mathbb R^{n-1} \to \mathbb R^n$ 
given by $\phi(x_1, \ldots, x_{n-1}) = (x_1, \ldots, x_{i-1}, c, x_i, \ldots, x_{n-1})$. Following the philosophy of the `ggeffects` package, for a more 
complex model $f_\beta$, we may visualize and interpret the effect of a (non-primary) variable of interest by plotting its marginalization at a finite (>1) 
set of values.

### Basic methods
We demonstrate some of the basic methods of `parameterized_model` objects. Consider some non-linear regression model $y \sim f_\beta(w, h, \ldots) + \varepsilon$ dependent on weight and height mesurements. Consider the parameterization
$(c, t, \ldots) \mapsto (w = ct^2, h = t, \ldots)$. Fixing $c$ (and the other variables, $\ldots$), we obtain a 1 parameteric family of observations with fixed BMI
and varying height. Doing similarly with $t$, we parameterize the observations with varying weight/BMI and fixed height.

```{r}
w <- rnorm(500, mean = 70, sd = 4)
h <- rnorm(500, mean = 170, sd = 10)

a <- rnorm(500)

y <- a + w/h^2 + h + w + w^2 * h + rnorm(500)


# model example
model <- lm(y ~ splines::ns(w,3) + splines::ns(h, 3) + splines::ns(w,3) %ia% splines::ns(h,4) + a)

# parameterize model
pmodel1 <- parameterize(model, parameterizations = list(w = \(t,c) c*t^2, h = \(t) t))

# parameterized model attributes
print(pmodel1, show_history = TRUE)

# underlying model
original_model(pmodel1)

# model parameterizations
parameterizations(pmodel1)

# new model variables
parameter_variables(pmodel1)
```

The methods are as follows:

* **`parameterize()`** — *Parameterize one or more predictor variables of a fitted model.*
  Takes a model and a named list of functions, expressions, or character strings defining the parameterizations. These are converted to functions and associated with predictor variables of the original model. When applied to an existing `parameterized_model`, the new parameterizations are composed with the existing ones and recorded in the parameterization history.

* **`parameterized_model()`** — *Construct a `parameterized_model` directly.*
  This is the low-level constructor underlying `parameterize()`. It takes an original model and a named list of parameterization functions, retains those corresponding to model predictors, determines the variables required by those functions, and stores the resulting parameterizations and their history alongside the original model.

* **`predict()`** — *Generate predictions from a parameterized model.*
  The `predict.parameterized_model()` method first transforms `newdata` according to the model's parameterizations and then delegates prediction to the original model's `predict()` method. Consequently, `newdata` is specified in terms of the parameter variables rather than the parameterized predictors.

* **`original_model()`** — *Extract the underlying fitted model.*
  Returns the original model stored inside a `parameterized_model`. If the supplied object is not a `parameterized_model`, it is returned unchanged.

* **`parameterizations()`** — *Extract the parameterization functions associated with a model.*
  By default, returns the model's current parameterizations. The `level` argument can instead be used to retrieve and compose a specified number of the most recent parameterization steps from the model's parameterization history.

* **`parameter_variables()`** — *Return the variables on which the parameterized model depends.*
  Extracts the unique variables appearing as arguments of the model's current parameterization functions. These are the variables that must be supplied when constructing prediction data for the parameterized predictors.

* **`parameterize_data()`** — *Apply a model's parameterizations to a data frame.*
  Evaluates each parameterization using the corresponding parameter variables in `newdata` and adds the resulting parameterized predictors to the data. The optional `level` argument controls how many levels of the parameterization history are applied.

* **`print()`** — *Display a summary of a `parameterized_model`.*
  The `print.parameterized_model()` method prints the underlying model, its parameter variables, and the current parameterization functions. Setting `show_history = TRUE` additionally displays the sequence of parameterizations previously applied to the model.

* **`is.parameterized_model()`** — *Test whether an object is a `parameterized_model`.*
  Returns a logical value indicating whether the object inherits from the `"parameterized_model"` class.

### Simultaneous confidence bands

#### Definition and Motivation:
For a regression model of the form $y \sim f_\beta(x) + \varepsilon$, the standard confidence band for predictions, $f_{\hat\beta}(x_0)$ is the set:
$$
  C_{\beta}(x_0) = [\hat f_\beta(x_0) - t_{1-\alpha/2, n-p} SE(\hat f_\beta)(x_0), \hat f_\beta(x_0) + t_{1-\alpha/2, n-p} SE(\hat f_\beta)(x_0)]
$$

The set-valued function $C_\beta: \Omega \to 2^\mathbb{R}$ is the pointwise confidence interval. In particular, one only draws pointwise inferences about $f_\beta$, effectively,
by means of hypothesis tests of the for $H_0: f_\beta(x) = f_0$, which we reject iff $f_\beta(x) \not\in C_\beta(x)$. One may naively attempt to extend this pointwise test
to a global test by means of multiple joint hypothesis tests, $H_0$ & $H_1$ & $\cdots$ & $H_n$--corrected with multiple hypothesis corrections. In the case where we 
correct uniformly accros the domain of interest, $\Omega$, we obtain the standard hyperbolic simultaneous confidence band: the set-valued function 
$C_\beta: \Omega \to 2^{\mathbb R}$ given by

$$
  C_\beta(x_0) = [\hat f_\beta(x_0) - c_\alpha SE(\hat f_\beta)(x_0), \hat f_\beta(x_0) + c_\alpha SE(\hat f_\beta)(x_0)]
$$
where $c_\alpha$ is chosen such that is the 95-percent quantile of $\sup_{x\in \Omega}\frac{\lVert f_\beta(x) - \hat f_\beta(x)\rVert}{SE \hat f_\beta(x)}$.
By construction, particulary, the supremum, we observe that this confidence band "considers" the covariance structure of the regression model.


Observe that there is not an elementary closed form for the distribution, in general. Hence, we compute it via simulation or bootstrap based methods. For nice models
(ie. generlized linear models) we can sample from the distribution of the regression coefficients, for less nice models, we must refit several models, then estimate. In particular, 
in p-ggeffectstermeffects, we implement two methods (in addition to the pointwise confidence band). For generalized linear models the band is computed on the scale of the linear predictor and then transformed, so it respects the range of the outcome (e.g. probabilities stay within 0 and 1).

#### Utility

In the case of regression models with more than 4 variables, the simultaneous confidence band based inference implemented in p-ggeffectstermeffects
allows far more restricted inferences. Indeed, the underlying foundational object of the ggeffects package, the `ggeffectterm_predictions` object, is a
marginalized data grid, together with its respective prediction. The coefficient based inference is determined from the observations, whereas 
(still essentially coefficient based) simultaneous confidence testing requires the additional specification of the domain (which can be lost).

# parameterized_model objects

## Overview
A `parameterized_model` is a data structure consiting of a tuple of a fitted regression
model, and a collection of maps that parameterize the continuous predictive variables
of the model. Moreover, there exists some auxiliary tracked iformation, ie. new parameters,
and a parameterization history.

The primary objective of parameterized models is the visualization of higher order data in terms of 
lower order parameteric families via marginalization. As an example, consider the fitted regression model:
$$
y = f(x_1, \ldots, x_n; \beta)\quad\text{ with parameterizations}\quad x_i = h_i(z_1, \ldots, z_m)
$$
Viewing the regression model as a function, notice that the data of the parameterized model determines 
the data of a model by pulling back by the $h_i$. We do note however, that the observed data for which 
$f_\beta = f(-; \beta)$ was fitted may not be contained in the image of $h = (h_i)_i$, and so the parameterized model
$f_\beta \circ h$ is almost never determined by the initial observations. For this reason, this parameterization
is primarily a tool for developing intuitions and visualizations. 

Indeed, in sufficiently nice scenarios (for instance if $h$ is smooth), the rank of the parameterized
model (viewed as the composition $f_\beta \circ h$) is less than or equal to the rank of $f_\beta$.
Particularly, by fixing arguments in $z$ (to obtain planes), we obtain more varied marginalizations
of $f_\beta$.

## Simple Example

Suppose we have some regression model $y \sim f_\beta(\operatorname{weight}, \operatorname{height}, \ldots)$. With parameterizations $(t, c, \ldots) \mapsto (ct^2, t, \ldots) = (\operatorname{weight}(t), \operatorname{height}(t), \ldots)$ (where the other function are the identity), we obtain co-level sets in c and $\ldots$ of subsets with fixed BMI,
and co-level sets in $t$ and $\ldots$ of subsets with fixed height, but variable weight and BMI.

# Plotting
trcp-ggeffectstermeffects extends the plotting feature of ggeffects toprovides _two_ additional plot types for surfaces: heatmaps, and heatmaps with

# Introduction

This case study demonstrates a workflow for **p-ggeffectstermeffects** in which fitting a regression model is deliberately separated from specifying prediction domains and drawing figures. We analyze the `heartfailure` dataset distributed with termeffects (originally from `dlookr`), treating **left ventricular ejection fraction (LVEF)** as a continuous outcome. We ask how its *adjusted association* with renal markers varies across creatinine, serum sodium, and age.

The example illustrates fivesix tools from the supplied p-ggeffects vignette:

1. **Spline interactions** allow a flexible two-variable response surface.
2. **`ggpredictterm_predictions()`** produces adjusted predictions on regular grids for heatmaps.
3. **`parameterize()`** transforms a *fitted* model into clinically meaningful prediction coordinates without refitting it.
4. **Heatmaps and parameterized overlays** (`term_heatmap()`, `term_layer()`) display both the fitted surface and nonlinear constant-eGFR trajectories in the original predictor coordinates.
5. **`ci_method = "coefficient"`, `plotterm_curves(..., use_scbband = TRUE"simultaneous")`** demonstratedemonstrates simultaneous uncertainty over a *specified prediction grid*.
6. **`test_simultaneous_predictions(..., f = f0)`** demonstrates simultaneous comparison with a specified reference function, including a linear reference surface. This is not a general test of linearity.

**Scope.** Every plot has at most two continuous focal coordinates (or one continuous coordinate and age strata). All other predictors are held at stated reference values. In the model-fitting stage, no plotting decisions are made. The resulting analysis is associative, not causal. The data are observational and small (299 patients); apparent nonlinear patterns may be unstable.

## 5. Define the nonlinear eGFR transformation

For demonstration we use the **2021 CKD-EPI creatinine equation**, which depends on serum creatinine (mg/dL), age (years), and sex. This is an estimated kidney-function measure, not a direct measurement. Its application to these historical records is retrospective.

\[
\text{eGFR} = 142 \cdot \min(C/\kappa, 1)^{\alpha} \cdot \max(C/\kappa, 1)^{-1.200} \cdot 0.9938^{A} \cdot (1.012 \text{ if female}),
\]
with $\kappa = 0.7$, $\alpha = -0.241$ for women and $\kappa = 0.9$, $\alpha = -0.302$ for men.

## 7. Limits of simultaneous inference after marginalization

The `test_simultaneous_predictions()` implementation works on a `ggeffectsterm_predictions` or `ggeffects_layerterm_layer` object, **not on the entire original regression function**. These objects store predictions on a chosen focal grid after the remaining model predictors have been marginalized (for example, fixed at representative values). This imposes important limitations:

- **Restricted domain.** The simultaneous test concerns only the generated grid of focal terms, not all combinations of predictors in the original model. A conclusion for the creatinine–sodium surface does not establish a corresponding conclusion for every age, sex, or diabetes status.
- **Marginalization is baked in.** The non-focal variables have already been reducedfixed according toat the prediction object's adjustmentreference schemevalues. The test cannot recover their full variation, interactions, or the original higher-dimensional domain from that object.
- **Scope depends on the prediction object.** A `ggeffects_layerterm_layer` can restrict the domain further to selected parameterized curves. A simultaneous band over such a layer does not provide simultaneous coverage over the entire background heatmap or over unplotted curves.
- **Finite-grid inference.** The critical value is computed for the generated prediction points; it is not automatically valid uniformly over a continuous region between those points.
- **A specified reference is not a general shape test.** Comparing against one linear `f0` only assesses that particular surface, at the chosen adjustment values. Rejecting it does not prove nonlinearity, and failing to reject it does not establish linearity. A fully general test of linearity would need to account for the family of possible linear functions and any uncertainty in estimated reference coefficients.

Thus, the demonstration above is intentionally a **simultaneous test against a fixed reference function on a marginalized grid**, rather than a global test of linearity of the fitted multivariable regression. The marginalization choices and grid must be reported alongside the result.

## 8. Questions to answer after rendering

- **Figure 1:** Is there evidence of a nonlinear creatinine–sodium interaction? Which regions have adequate observational support?
- **Figure 2:** Along a constant-eGFR curve, does predicted LVEF change appreciably with age? If so, eGFR alone does not capture the fitted age–creatinine association.

- **Figure 4:** Is the specified linear reference surface compatible with the fitted predictions over the grid? What does the test establish—and what does it not establish—about linearity?

## 9. Important qualifications

1. **No causal interpretation.** These are conditional associations in an observational dataset.
2. **Small sample.** Nonlinear interactions may be weakly identified. Consider reduced splines, bootstrap stability checks, and out-of-sample validation.
3. **Sparse support.** Limit grids and overlays to observed or well-supported regions; not all constant-eGFR curves are represented in the data.
4. **LVEF is the response.** The example does not use death or follow-up time, even though those fields are available.
5. **Consistent adjustment.** Verify the adjustment profile recordedprinted bywith each `ggpredictterm_predictions()` result, particularly for sex and diabetes. Fix sex before interpreting sex-specific eGFR contours.
6. **Separate fitting from presentation.** To change the grid, eGFR transformation, or plotting style, update Parts II–III. The fitted `model` in Part I remains unchanged.

## Feature 2 — Parameterize a fitted model

`parameterize()` constructs a prediction model by expressing one or more original predictors as functions of new coordinates. It reuses the coefficients of the fitted model; the transformation affects prediction inputs rather than estimation.

For a simple demonstration, define a **synthetic renal-function index** as a function of creatinine and age. This is *not* clinical eGFR or the CKD-EPI equation; its sole purpose is to illustrate a nonlinear change of prediction coordinates. A validated eGFR equation could replace it in an applied analysis (see the vignette "termeffects feature demonstration", which uses the 2021 CKD-EPI equation).

\[
R = \frac{100\exp[-0.01(A-60)]}{C}, \qquad
C = \frac{100\exp[-0.01(A-60)]}{R}.
\]

```{r parameterize-model}
renal_index <- function(creatinine, age) {
  100 * exp(-0.01 * (age - 60)) / creatinine
}

creatinine_from_index <- function(index, age) {
  100 * exp(-0.01 * (age - 60)) / index
}

pmodel <- parameterize(
  model,
  parameterizations = list(
    serum_creatinine = function(index, age) {
      100 * exp(-0.01 * (age - 60)) / index

  )
)

parameter_variables(pmodel)
```

# Part IV — Limitations of plotting, inference, and parameterization

## Plotting and dimensionality

- **Heatmaps show only two continuous focal variables at a time.** They cannot display the full predictor space of a higher-dimensional model. Other predictors are adjustedheld or conditioned onconstant. A `ggeffects_layerterm_layer()` also requires a base surface with two continuous focal variables; its parameterizations map back to those primary variables and use at most two new coordinates. Layers therefore support curves or families of curves on that surface, not arbitrary high-dimensional overlays.

## Simultaneous inference and marginalization

- **Inference applies to the generated grid and its adjustment profile.** Non-focal predictors have already been marginalized or fixed at selected values. The simultaneous bands and reference-function test therefore concern predictions at those marginal or conditional values; they do not establish simultaneous coverage over omitted predictors or their interactions. Changing the adjustment profile can change the function being assessed.
- **The critical value is estimated using a finite grid.** The grid approximates the supremum over the prediction domain; it is a numerical method for estimating the simultaneous critical value, not a restriction of the intended band to sample or grid points. Coverage is intended to apply between grid points as well, with accuracy depending on how well the generated grid represents the domain.
- **The current scope iscan globalbe chosen.** The`ci_scope implementation= currently"global"` forces(default) globalmakes scope,the soband simultaneous over the whole grid; `"faceted"` and `"curve"` give separate simultaneous adjustments by facet areor notby available through this pathcurve.
- **The reference-function test is not a general shape or linearity test.** It compares predictions with one supplied function. For non-standard models and parameterizations, defining the relevant reference function in the original predictor coordinates may not be straightforward; it must return one numeric value at each evaluation point and use argument names matching variables of the original model predictorspredictions. Standard hypotheses such as linearity also generally require fitting an additional constrained or reference model, with its estimation uncertainty accounted for, rather than simply supplying one fixed function. ## Parameterization and default prediction domains

- **Parameterization inputs are treated as numeric.** This makes categorical transformations unsuitable and can remove the meaning of factor levels. The implementation does not generally verify that transformed predictors are finite or scientifically plausible.
- **Unknown parameterization names canare bean silently ignorederror.** Only names matching model predictors (or variables of an existing parameterization) are retainedaccepted, so a typo canstops leavewith a message rather than leaving the model unparameterized rather than produce an error.
- **Default parameter-coordinate bounds are heuristic, centered rectangular boxes.** The range-generation code searches symmetric boxes around zero, shrinking them until their sampled and optimized image fits within the observed range of the original predictor, then expanding dimensions individually. This follows the zero-centered parameter-coordinate convention.
- **The bounding-box heuristic may not suit compact or irregular parameterizations.** For bounded, periodic, many-to-one, or non-rectangular mappings, a single centered rectangle may omit valid regions or include combinations that map outside the original predictor's observed range. Its image bounds are estimated using random samples and local optimization, which can miss extrema. If the search cannot find a suitable box, it warns and returns the last box, so downstream grids can still contain out-of-range or invalid transformed values. Giving the ranges with `values` avoids the search.
